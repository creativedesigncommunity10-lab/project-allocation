# Meetings & Agenda — Phase 1 Backend Foundation

## Changes
- Adds central Meetings database configuration through `MEETINGS_SPREADSHEET_ID`.
- Validates the five expected tabs and exact header order without silently creating or overwriting tabs.
- Adds division-scoped API actions:
  - `meetingsHealth`
  - `meetingDirectory`
  - `meetingList`
  - `meetingCreate`
- Loads participant names and selectable projects from the active division's existing `Users` and `Projects` sheets.
- Derives `DivisionID` from the authenticated request context. Client-supplied division identifiers are not accepted for meeting records.
- Validates selected participants against active users in the current division.
- Includes the creator as a participant only if the creator is an active user in the current division. A central Admin switching into another division is not silently added as a cross-division participant.
- Keeps project association optional and stores a project name snapshot when selected.

1. `meetingsHealth` — validates spreadsheet access, all five tabs, and header order.
2. `meetingDirectory` — returns only active members and active projects from the active division.
3. `meetingList` — returns only meetings, participants, and MoMs whose `DivisionID` matches the active division.
4. `meetingCreate` — creates a meeting and selected participant rows in the central database, with DivisionID generated by the backend.
